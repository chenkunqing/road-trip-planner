# 技能版本合并经验

## 场景描述
当用户要求更新技能时，可能遇到GitHub仓库上的版本是精简版，而本地已有更完整的版本。需要将两个版本的功能合并。

## 合并步骤

### 1. 添加tap源并安装
```bash
hermes skills tap add chenkunqing/road-trip-planner
hermes skills install travel-itinerary --yes --category productivity
```

### 2. 比较版本差异
- **精简版（GitHub）**：152行，专注于攻略生成核心功能
- **完整版（本地）**：434行，包含HTML地图、部署、路线审查等高级功能

### 3. 合并原则
1. **保留新版本的结构**：信息收集表格、触发条件、启动流程
2. **合并高级功能**：HTML地图创建、服务器部署、坐标校验等
3. **去重**：避免重复内容，保持文件简洁
4. **保持版本兼容**：确保新版本包含所有旧版本功能

### 4. 合并后的验证
检查以下功能是否都存在：
- ✅ HTML交互式地图创建
- ✅ 服务器部署流程  
- ✅ 高德地图API key获取
- ✅ 多日行程彩色路线图
- ✅ 坐标校验
- ✅ 常见陷阱（12条）
- ✅ 路线审查
- ✅ 路线图创建
- ✅ 信息收集表格
- ✅ 应急方案
- ✅ 输出模式

## 注意事项
1. **references目录**：包含具体示例和详细技术文档
2. **templates目录**：包含可复用的模板文件
3. **版本号更新**：合并后记得更新版本号（如v2→v3）
4. **GitHub推送**：及时推送更新到仓库，保持版本同步

## 常见问题
1. **GitHub版本落后**：用户可能在本地修改了技能但未推送到GitHub
2. **功能重叠**：不同版本可能有相似但不完全相同的内容
3. **引用文件丢失**：合并时要注意references和templates目录的完整性
