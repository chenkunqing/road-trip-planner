# 内容丰富度示例与常见陷阱

## 内容丰富度示例（用户期望的详细程度）

```
门票70元/人+自驾环湖100-150元/车 · 可以开车进去自驾环湖70公里！ · 新疆海拔最高(2073米)面积最大的高山湖泊，被叫做"大西洋的最后一滴眼泪"——大西洋水汽的最东端 · 湖水蓝得不真实，6月湖边开满黄色紫色野花背景是雪山360度无死角 · <strong>玩法(3-4小时)：</strong>建议逆时针方向(先北岸下午光线从南照过来拍北岸最好看)→看到漂亮地方随时停车→必停：西海草原(湖边最大草地野花区拍照最佳)→天鹅乐水区域(碰运气看天鹅)→日落约21:30在西岸最美太阳落入雪山湖面 · <strong>注意：</strong>湖边风非常大气温约10-15°C必须穿外套甚至冲锋衣！
```

### 如何达到这种丰富度
1. **门票信息详细化**：不只是"70元"，而是"门票70元/人+自驾环湖100-150元/车"
2. **体验描述具体化**：不只是"湖很美"，而是"湖水蓝得不真实，6月湖边开满黄色紫色野花背景是雪山360度无死角"
3. **玩法步骤清晰化**：用箭头连接步骤，标注每步大约时间
4. **注意事项实用化**：不只是"注意安全"，而是"湖边风非常大气温约10-15°C必须穿外套甚至冲锋衣！"

## 常见陷阱

1. **信息割裂**（最严重！）：把景点介绍、门票、玩法分开写在不同section→用户需要来回翻→体验极差。用户原话："信息有一点点割裂"。解决方法：所有信息嵌入时间线对应位置，像用户发来的参考攻略图片那样写。
2. **只写景点名不解释**：用户可能不知道"唐布拉百里画廊"是草原/公路/瀑布→必须用大白话说清楚"它是什么"
3. **导航链接用显示名**：marker显示名带emoji和day标记（如"Day5 🇨🇳 霍尔果斯"），无法在高德地图搜索。必须用navName字段存真实地名
4. **坐标不准确**：网上查的坐标可能偏差20-30km，尤其是景区内的具体景点。以附近已知城市为参考点校验
5. **时间过紧**：没考虑停留拍照、排队、吃饭、找路的时间
6. **忽略人员组成**：年轻人和长辈的耐受度完全不同
7. **景点重复体验**：同一趟行程不需要两个类似景点（如两个观光草原→砍一个换不同类型）
8. **不考虑当地时差/作息**：如新疆实际晚2小时，按北京时间9点出发=当地7点，太早了
9. **赶路日连续安排**：连续两天6h+车程会让人崩溃，尽量把辛苦日拆分到隔天
10. **晚归+早起冲突**：如23:00回酒店但第二天要06:30出发=只睡6h，对长辈不友好
11. **国内地图服务不可访问**：OpenStreetMap在国内被墙，必须使用高德地图、腾讯地图等国内服务。用户报告"地图看不了"时，首先检查是否使用了国外地图服务
12. **文件发送问题**：QQ平台MEDIA附件发送可能失败，需要直接在聊天窗口输出内容作为备选方案

## 用户偏好的具体内容格式

用户期望的景点攻略格式（从用户发来的参考图片中总结）：
```
⭐ <strong>景点名</strong> 描述<br>
<span style="font-size:12px;color:#666;">门票信息 · 它是什么描述 · <strong>玩法：</strong>步骤1→步骤2→步骤3 · <strong>注意：</strong>注意事项</span>
```

关键要点：
1. **门票信息放在最前面**：用户最关心"多少钱"
2. **用"·"分隔不同信息点**：让信息更紧凑易读
3. **玩法用箭头连接**：清晰展示步骤流程
4. **注意事项单独标注**：用"注意："前缀
5. **详细信息用小字**：用`<span style="font-size:12px;color:#666;">`包裹

## 工作流程（分阶段交付）

1. **大框架阶段**：先出每天去哪、大致路线，让用户确认方向
2. **方案对比阶段**：如果用户有参考方案，列出优缺点对比表让用户选择
3. **调节阶段**：根据用户反馈增删景点、调整节奏（每天车程、出发时间等）
4. **汇总变更**：每次调整后，明确告知"砍掉了什么/保留了什么/为什么"
5. **最终版阶段**：输出完整时间线文档（一次性交付完整版，不要中途频繁汇报）

## 关键交互细节
- 用户可能发来参考攻略（图片/文字），要认真对比分析优缺点
- 用户可能逐步提出约束（人员年龄、体力、偏好、预算），每次都要重新评估可行性
- 出发时间要根据当地实际作息反复确认（用户可能觉得某个时间太早/太晚）
- 某个景点值不值得去，要给出"性价比分析"（如等4.5h看日落+第二天要早起=不合理）

## 核心原则（按重要性排序）

1. **不割裂**：每个景点的所有信息（介绍、门票、怎么玩、注意事项）都写在对应的时间段内。绝对不要单独拆出来做表格或汇总章节。
2. **时间线驱动**：以"几点到几点做什么"为主轴，所有信息嵌入时间线。参照格式：用户发来的那种"几点到几点+【景点名】+门票+玩法"一体化写法。
3. **导航明确**：每个地点都写清楚"📍导航搜什么关键词"，告诉用户在高德/百度地图里搜什么。
4. **景点要解释**：不能只写景点名，必须用1-3句通俗大白话解释"它是什么/为什么值得去/长什么样"，让没去过的人脑海中能浮现画面。
5. **实用性优先**：门票怎么买、能不能开车进去、要不要提前预约、穿什么衣服——这些执行层面的信息比抒情描写重要得多。
